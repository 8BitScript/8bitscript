# Commander X16

[x16emu](https://github.com/X16Community/x16-emulator) is the reference
emulator for the Commander X16 — `8bs build --target cx16` links against
llvm-mos's `cx16` platform (see [LLVM-MOS](llvm-mos.md)), which shares the
C64's KERNAL jump table and BASIC memory layout closely enough that both
targets' `.prg` files load the same way.

Unlike VICE, atari800, and FCEUX, there is no packaged build of x16emu for
macOS or Linux yet — it's built from source, which is normal for the X16
community's own emulator (the machine itself is still evolving).

## Build from source

Both platforms need SDL2 first:

```bash
# macOS
brew install sdl2

# Debian/Ubuntu
sudo apt install libsdl2-dev

# Arch/Manjaro
sudo pacman -S sdl2
```

Then clone and build:

```bash
git clone https://github.com/X16Community/x16-emulator.git
cd x16-emulator
make
```

This produces an `x16emu` binary in the repository. Put it somewhere on your
`PATH` — `~/.local/bin` or `/usr/local/bin` are the usual choices — so `8bs
run cx16` can find it.

## Verify

```bash
x16emu -h
```

should print its usage. `8bs doctor` checks that `x16emu` exists on `PATH`;
unlike the packaged emulators, it doesn't check a version, since this
project has not confirmed a `--version` flag exists.

## Run

```bash
8bs run cx16
```

`8bs run` passes the built `.prg` as `-prg <file> -run`, confirmed against
the X16Community/x16-emulator README. There's no NTSC/PAL split to pick —
the X16 is a single fixed hardware spec, not a family of vintage machines
with region-dependent crystals (see the comment on `FRAME_SYNC.cx16` in
`packages/backend-6502` for what that means for frame timing).

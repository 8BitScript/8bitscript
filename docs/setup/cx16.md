# Commander X16

`8bs setup cx16` builds `x16emu` and a matching `rom.bin` from upstream
source and installs them under `/opt/commander-x16`, with launchers in
`/usr/local/bin`. The emulator and the ROM have to be a pair; an AUR
package that drifts from its ROM is why this project builds both.

```
8bs setup cx16
8bs setup cx16 --repair
```

## Host packages

macOS (Homebrew):

```
brew install git cmake python pkgconf sdl2 cc65 lzsa
```

Arch / Manjaro:

```
sudo pacman -S --needed base-devel cmake git python zlib sdl2-compat
pamac build cc65 lzsa
```

Ubuntu / Debian:

```
sudo apt-get install -y build-essential cmake git python3 zlib1g-dev libsdl2-dev pkg-config cc65
```

`lzsa` is not in Debian/Ubuntu. Build it from
[emmanuel-marty/lzsa](https://github.com/emmanuel-marty/lzsa) and put
the binary on PATH before `8bs setup cx16`.

On macOS a plain symlink `x16emu → /opt/commander-x16/x16emu` dies with
`Cannot open /usr/local/bin/rom.bin!`. Setup writes a wrapper that
passes `-rom` explicitly. Linux keeps the symlink. `8bs setup cx16 --repair`
fixes a broken macOS symlink without rebuilding.

Studio's in-editor tab is `8bs run cx16 --web` (the WebAssembly
emulator). That path does not need a native `x16emu`.

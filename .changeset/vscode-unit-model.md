The extension now runs a **program** of a project on a **system** in a **runtime**, with its **inputs**, and the three runtimes are three independent commands. Nothing here changes the side-bar layout yet; it is the model and the commands the redesigned launcher is built on (see `editors/vscode/docs/unit-model.md`).

- **Editor, Browser, Native.** `8bitscript.runEditor` (the WebAssembly page in an editor tab), `8bitscript.runBrowser` (the same page in the system browser, no tab) and `8bitscript.runNative` (the machine's own emulator) each run on their own: Native no longer needs a WebAssembly run first, and Browser needs no tab. `8bitscript.runUnit` takes the runtime as an argument. For the X16, `x16emu: true` runs the real emulator as WebAssembly.
- **No hidden default.** Plain `8bitscript.run` uses the runtime last used for that program, else the Editor (Native when the now-deprecated `preferWebPreview` is off), else whichever works. It no longer applies a built-in list of "web-ready" machines. A runtime that cannot work is not run: you are told why (the CLI's own reason, "x64sc is not installed", "web has no native emulator") and offered the fix.
- **Read from the CLI, not hard-coded.** The project (its programs, titles, targets, systems and problems) comes from `8bs project --json`, the runtimes of each machine and whether it takes `--pal` from its row in `8bs targets --json`. A CLI older than those falls back to the old config reader and a small built-in table, and says so.
- **Inputs.** A program's `define`s are passed as `--define NAME=VALUE`, only where they differ from the program's own values; a value that does not fit its kind is refused before anything runs. `--locale` is passed when a locale is given.
- **Several runs at once.** A run is identified by (project, program, system, runtime): starting it again replaces it, another runtime of the same program runs beside it, and `8bitscript.stop` takes a `runId` to end exactly one. Each run records the exact `8bs` command it was started with. (The CLI keeps one live-status report per machine and mode, so two WebAssembly runs of the same machine share the status panel.)
- **Remembered per program, per workspace.** The last runtime, the last system and the input values live in the workspace's state, not in `settings.json`.
- **Tasks.** The `8bs` task type gains `boot`, `runtime` (`editor`, `browser`, `native`), `define`, `locale`, `system`, `profile` and `hardware`; Tasks: Run Task also lists each program's WebAssembly run in the browser where the machine has one. A tasks.json entry's `web: true`, which was declared as "run `--web`" but never reached the command, now runs in the browser.
- **Open Entry opens the selected program's entry** (it opened `main`'s regardless), and a new **Reveal Program in Config** command puts the cursor on its key.

Compatibility. Every command id keeps working for this release. `8bitscript.boot` is now `8bitscript.openBareEmulator` (the old id is a hidden alias); `8bitscript.selectProject` and `8bitscript.selectSystem` move to the side bar (they still work, hidden from the palette, with a one-time notice). `8bitscript.system` no longer lists five machines to choose from: any machine id the CLI lists is accepted. The extension no longer switches your file icon theme on for you when it is installed (`configurationDefaults`): it asks once.

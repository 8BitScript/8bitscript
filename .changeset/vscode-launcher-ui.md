The side-bar launcher is rebuilt around what you run. It is a list of the project's programs, grouped, each row with three labelled buttons — **Editor** (the WASM build in an editor tab), **Browser** (the WASM build in your web browser) and **Native** (the machine's real emulator) — so any program is one click from any of them, and none needs another to be running first. Above the list are the Project and System pickers, the System's fitted hardware, region and language shown as a summary with a gear that opens the hardware tab, and a filter for a long list. The selected program opens a card: its description, its source file (a link that opens *that* program's entry, not the project's `main`), the reason a runtime is unavailable with the fix beside it (install the emulator, run Doctor, or use another runtime), an **Inputs** form for the program's `define`s with a Reset to defaults, **Build** (its tooltip says it writes `dist/<program>.prg` and the size report and runs nothing), **Command** (the exact `8bs` line a click runs, with `--define` flags for changed inputs, copyable) and a ⋯ menu with **Open bare emulator**, Copy command and Reveal in Explorer. **Running** shows every live run, several at once for the same program (Editor beside Native), each with its own Stop, Show tab and Open in browser, its address and QR code, its size table and its command.

Gone: the two identical file-page icons (one opened the project details, the other the entry file of `main` whatever you had picked), the Run split button and its chevron sliver with "Run in emulator" buried in it, the "fitted as" link that looked like plain text, Boot as a primary button, and the Studio split button (Studio, Doctor and Project details are now under Tools). The old rule that silently chose WASM for some machines and the native emulator for others is no longer applied: the primary button is the runtime you last used for that program, Editor the first time (Native if the deprecated `preferWebPreview` setting is off), and a runtime that cannot work is shown disabled with its reason, still reachable by keyboard.

It is keyboard- and screen-reader-complete: one tab stop for the whole program list with arrow keys inside it (Enter runs a program's primary runtime), menus with roving focus and Escape, `aria-disabled` rather than `disabled` so a disabled button can still be reached and heard, a visible focus ring everywhere, and a layout that keeps working from 260 px up and in High Contrast. The page is built from the editor's own colour variables, so every theme works, and uses a 3 KB subset of the Codicons font (vendored with its licences) for icons.

Browser runs and the Inputs form need the unit commands and `8bs project --json` from the toolchain; until a run uses them, Browser says so instead of running something else, and a project whose toolchain predates them shows no Inputs.

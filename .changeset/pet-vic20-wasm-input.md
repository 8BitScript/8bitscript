**The PET's and the VIC-20's wasm builds take the keyboard.** `8bs run pet --web`, `8bs run vic20 --web` and the editor's tab built a program whose arrows did nothing: the portable `@8bitscript/input` on those two machines scans the keyboard matrix through PIA 1 (PET) and the VIAs (VIC-20), and a wasm build has no chip behind those addresses — plain bytes nothing writes, which the PET's layer inverted into "every key held from frame one", so no press ever began. Each package now carries a `.web` twin of its input layer (`input.pet.web.8bs`, `input.vic20.web.8bs`, the way the C64's `input.c64.web.8bs` already did) that reads the one byte the page writes its key snapshot to — arrows, Enter for RETURN, Escape for RUN/STOP — for the 40-column PETs, the 80-column 8032 and every VIC-20 memory fit alike. The machine-level `@8bitscript/pet/keyboard` and `@8bitscript/vic20/keyboard` still read the chips and see nothing on the wasm build; a portable program never touches them, and each machine's `emulator.wasm.limits` says so. On the VIC-20's wasm build `Input.CONFIRM_LABELS` is `RETURN` where the native build's is `RETURN OR FIRE`: there is no stick to plug into a page. Pinned by `packages/cli/test/web-pet.test.mjs` and a key test in `web-vic20.test.mjs`, which press keys the way the page does and read the tallies the program prints.

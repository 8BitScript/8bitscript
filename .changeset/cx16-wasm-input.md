"@8bitscript/cx16": patch

**The Commander X16's wasm build takes the keyboard, and a program that uses `@8bitscript/input` builds for it.** `8bs build --target cx16 --web`, `8bs run cx16 --web` and the editor's tab failed on any such program, 2048 and `examples/joystick` among them, with `'input_poll': 'asm' blocks ... never lowered on the web target`. The X16's input layer is KERNAL calls in `asm6502`, and the wasm backend lowers none of them. The package now has `input.cx16.web.8bs`, a `.web` twin of its input layer like the PET's, VIC-20's and C64's. Once a frame it reads the byte the page writes its key snapshot to: the arrows, Enter for confirm and Escape for cancel. That byte is `text.CELL_COUNT * 2 + 2` (8514), `agreementFor()`'s default, just behind `text.cx16.web.8bs`'s two planes. A wasm build has no SNES pads and no pointer. `pointer()` is false, and `Input.CONFIRM_LABELS` is `RETURN`, where the native build's is `RETURN OR START`. `emulator.wasm.limits` now describes this instead of saying the input does not build. `packages/cli/test/web-cx16-input.test.mjs` pins the formula and tallies poked presses. `packages/compiler/test/cx16-web-twin.test.mjs` checks that the twin exports the same names as `input.8bs`.
